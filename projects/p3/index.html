Abstract

This project reproduces a scaled PointPillars-style 3D detection pipeline with candidate-owned pillarisation and then measures how detection degrades as point-cloud observations become sparse, noisy, or range-limited. The scaling is explicit so that the study remains feasible under restricted compute while preserving the core representation and evaluation logic.

Problem

Research question. How does pillar-based 3D detection degrade under controlled point-cloud corruption and reduced observation quality?

The objective is not leaderboard-scale training. The completed project must demonstrate representation ownership, a verified clean baseline, controlled corruption protocols, compute profiling, and failure analysis.

Method

  1. Calibrated point cloud.Load point clouds with explicit coordinate axes, spatial range, and preprocessing rules.
  2. Pillarisation.Assign points to pillars and construct pillar features with deterministic tests for indexing and aggregation.
  3. Pseudo-image detector.Scatter pillar features into a pseudo-image and train a scaled backbone/detection head.
  4. Robustness protocol.Freeze the detector and vary controlled dropout, sparsity, noise, and range conditions.

Experiments

DatasetScaled KITTI-style 3D detection setup with documented split and classes.
Clean baselineEstablish reproducible performance before applying corruption.
RobustnessSeverity curves for point dropout/sparsity/noise/range degradation.
Outputs3D detection metrics, severity curves, BEV examples, compute profile, ablation, and code when verified.

Failure analysis

The failure analysis will distinguish sensing degradation from representation/model limitations, with particular attention to distant objects, sparse occupancy, orientation, and occlusion-like point loss.

Reproducibility

The final release will publish preprocessing bounds, pillar parameters, corruption seeds, checkpoint/config metadata, evaluator settings, environment, code commit, and compute measurements.

Project status is reported conservatively. Unverified metrics, novelty claims, and unavailable artefacts are not presented as completed work.
