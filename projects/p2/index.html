Abstract

This project develops a compact RGB-D visual-odometry pipeline for studying camera-motion estimation when independently moving objects contaminate image correspondences. The emphasis is on explicit geometry, coordinate-frame conventions, robust pose estimation, trajectory evaluation, and failure analysis rather than on building a full SLAM system.

Problem

Research question. How robustly can camera motion be estimated when parts of the observed scene are independently moving?

The project is constrained to a compute-feasible visual-odometry pipeline. Geometry and state-estimation logic must be implemented and tested explicitly before any dynamic-scene extension is evaluated.

Method

  1. Synchronized RGB-D observations.Load colour/depth frames with explicit intrinsics, depth conventions, and frame definitions.
  2. Correspondence and 3D geometry.Generate candidate matches and back-project valid observations into metric 3D coordinates.
  3. Robust pose estimation.Reject inconsistent/dynamic observations and estimate the SE(3) transform with a robust objective.
  4. Trajectory composition.Compose frame-to-frame transforms and diagnose drift using trajectory-level errors.

Experiments

ScopeFrame-to-frame / short-window RGB-D visual odometry; not a full SLAM claim.
EvaluationSelected TUM RGB-D sequences with fixed alignment and ATE/RPE definitions.
RobustnessDynamic correspondences, low texture, blur, depth holes, and occlusion.
OutputsTrajectory plots, correspondence diagnostics, ATE/RPE tables, runtime, failure cases, and code when verified.

Failure analysis

Failure cases will be organised by observed cause—such as low texture, depth invalidity, dynamic occlusion, or poor geometric conditioning—rather than by a prewritten marketing taxonomy.

Reproducibility

The final release will include camera/frame conventions, sequence list, evaluator settings, transform tests, environment, code commit, and the exact commands used to reproduce trajectory metrics.

Project status is reported conservatively. Unverified metrics, novelty claims, and unavailable artefacts are not presented as completed work.
